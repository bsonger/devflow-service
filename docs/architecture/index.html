Core Concepts

ConceptOwnerDescription
Manifest release-service Immutable build-side snapshot: git revision, image ref, service/workload snapshots. Created once, never mutated.
Release release-service Immutable deploy-side snapshot: environment, strategy, steps, app config, routes. Progresses through ordered steps.
Bundle release-service Rendered K8s manifests (Deployment, Service, ConfigMap, VirtualService) published as an OCI artifact.
Env Overlay config-service Per-environment ConfigMap values from git config-repo, injected at bundle render time.
Intent release-service Async execution queue for release steps, with lease-based worker competition.
Runtime observer runtime-service Polls Kubernetes workload/pod state; writes rollout progress back to release-service. PostgreSQL-free by design.

Assumptions

  1. Pre-production environment only — committed manifests target a single pre-production cluster. Production topology may differ.
  2. telemetry-service is planned, not implemented — shown as a future concern only.
  3. Single PostgreSQL cluster — all stateful services share one CloudNativePG cluster.
  4. runtime-service is PostgreSQL-free — in-memory state rebuilt from K8s observation. Empty after restart until sync completes.
  5. OCI registry is in-cluster zot — pre-production only. Production may use an external registry.
  6. Rollout observer watches Deployments only — Rollout (Argo Rollouts) support is planned but not yet implemented.
  7. ArgoCD Application source is OCI artifact — not a git repository. The published bundle is the deployment source of truth.
  8. Service-to-service HTTP uses shared downstreamhttp client with OTel trace propagation.
