# M005/S02 — Research

## Summary

S02 is a targeted code-and-contract slice centered on three active requirements: R036 (stable rollout identity labels), R037 (supplementary trace annotations without identity responsibility), and R038 (drift-prone annotations kept out of Argo desired state by default). The current code already satisfies the first two requirements structurally: `internal/release/service/release_bundle.go` injects the canonical release/application/environment labels onto both workload object metadata and pod-template metadata, `internal/runtime/observer/kubernetes_runtime.go` and `internal/runtime/observer/release_rollout.go` consume those labels as the authoritative identity surface, and `internal/release/service/release.go` writes only OpenTelemetry trace/span annotations onto the Argo `Application`. S01’s audit and drift proof confirm the remaining risk: release rendering still blindly copies `manifest.WorkloadConfigSnapshot.Annotations` onto both workload object metadata and `spec.template.metadata.annotations`, while runtime-service independently patches `kubectl.kubernetes.io/restartedAt` onto live Deployments.

The primary recommendation is to make the metadata contract explicit in code at the release-rendering boundary instead of relying on docs plus a narrow Argo `ignoreDifferences` rule. Build a release-owned metadata filter/partition seam that preserves required identity labels, allows supplementary diagnostic annotations only on explicitly approved surfaces, and rejects or strips drift-prone annotations from Git/desired-state workload rendering by default. Then update tests and docs around that seam. This matches D012–D015, keeps runtime observers label-driven as already implemented, and avoids the anti-pattern called out in R047 of solving the problem mainly with broader ignore rules.

## Recommendation

Implement S02 at the release-renderer seam first, not in runtime-service. Specifically:

1. Introduce a small release-owned metadata contract helper near `buildReleaseWorkloadResource` that:
   - overlays the required identity labels exactly as today;
   - treats workload/pod-template annotations as an allowlisted supplementary surface rather than a blind copy-through;
   - excludes known drift-prone/system-mutated annotations such as `kubectl.kubernetes.io/restartedAt` from rendered desired-state resources.
2. Keep `applyReleaseApplicationMetadata` label behavior intact, and keep Argo `Application` annotations restricted to `otel.devflow.io/trace-id` and `otel.devflow.io/parent-span-id`.
3. Add tests that prove identity survives on labels, trace/span remain supplementary, and disallowed annotations do not appear on rendered desired-state surfaces.
4. Update the repo-tracked contract docs/verifier so S03 can focus on the live Argo sync repair rather than re-deciding the contract.

This is the lowest-risk path because runtime observers already consume labels only, so tightening release-rendered annotations should not require changes to `internal/runtime/observer/kubernetes_runtime.go` or `internal/runtime/observer/release_rollout.go` beyond maybe adding/refreshing proof tests. It also keeps future Rollout compatibility open because `buildReleaseWorkloadResource` already emits both `Deployment` and Argo `Rollout` objects from one shared metadata assembly path.

## Implementation Landscape

### Key Files

- `internal/release/service/release_bundle.go` — the central seam for S02. `buildReleaseWorkloadResource` currently copies `manifest.WorkloadConfigSnapshot.Labels` and `manifest.WorkloadConfigSnapshot.Annotations`, then overlays required labels and reuses the same `annotations` map for both workload object metadata and `spec.template.metadata.annotations`. This is the best place to enforce R036/R037/R038.
- `internal/release/service/release_bundle_test.go` — current coverage proves required labels override user-supplied collisions and that arbitrary annotations survive into the pod template. S02 should extend/change these tests to codify the new annotation-placement rules.
- `internal/release/service/release.go` — `applyReleaseApplicationMetadata` already cleanly splits labels vs supplementary OpenTelemetry annotations; preserve this behavior and make it the reference handoff surface. `releaseApplicationIgnoreDifferences` is still present, but S02 should not expand it broadly.
- `internal/release/service/release_argo_test.go` — verifies Argo `Application` metadata and current restartedAt ignore rule. Useful for protecting the handoff contract while S02 narrows desired-state annotation placement.
- `internal/release/domain/types.go` — canonical label constant definitions (`devflow.io/release-id`, `devflow.application/id`, `devflow.environment/id`). Any new helper should import these instead of introducing duplicate string literals.
- `internal/runtime/observer/kubernetes_runtime.go` — proof that runtime identity is already label-only. `labelsMatchRuntimeSpec`, `releaseOwnedSelector`, and `runtimeSpecFromDeployment` are the key consumer functions to cite and protect with verification.
- `internal/runtime/observer/release_rollout.go` and `internal/runtime/observer/release_rollout_test.go` — proof that rollout writeback derives release/application/environment context from observed workload labels, with only a narrow fallback from missing environment label to persisted workload environment. This fallback is important: S02 should avoid removing labels or weakening them.
- `internal/runtime/service/service.go` — runtime restart patch owner for `kubectl.kubernetes.io/restartedAt`. S02 likely should not change this file; instead it should ensure this runtime signal never becomes required desired-state metadata.
- `docs/resources/metadata-contract-audit.md` — canonical surface matrix from S01. Update this once the code contract is tightened so planner/executor/s03 all read the same surface rules.
- `docs/resources/metadata-drift-proof.md` — preserve as the proof package for why restartedAt is treated as drift-prone/system-mutated.
- `docs/resources/release.md` and possibly `docs/system/flow-overview.md` / `docs/system/runtime-observer.md` — reader-facing contract docs that should align to the enforced code seam after implementation.
- `scripts/verify-metadata-audit.sh` — the existing narrow verifier. S02 should extend it to assert the new contract boundary if docs/code strings change.

### Build Order

1. **Codify the release-rendering contract first** in `internal/release/service/release_bundle.go`, because that single path fans out to Deployment and Rollout rendering and unblocks all downstream verification.
2. **Lock it with unit tests** in `internal/release/service/release_bundle_test.go` and keep Argo handoff tests green in `internal/release/service/release_argo_test.go`. This proves R036/R037/R038 locally before any doc churn.
3. **Refresh docs and the verifier** (`docs/resources/metadata-contract-audit.md`, `docs/resources/release.md`, `scripts/verify-metadata-audit.sh`) once the code is settled, so S03 inherits a stable contract instead of rediscovering it.
4. **Only then consider live-sync investigation in S03.** S02 should hand off a clear rule set and proof that drift-prone annotations no longer originate from desired-state rendering by default.

### Verification Approach

- Focused unit tests:
  - `go test ./internal/release/service -run 'TestBuildReleaseBundle|TestApplyReleaseApplicationMetadata|TestBuildArgoApplication'`
  - `go test ./internal/runtime/observer -run 'TestDeriveReleaseRolloutContext|TestReleaseOwnedSelector'`
- Contract verifier:
  - `bash scripts/verify-metadata-audit.sh`
- Optional wider safety check after code/doc updates:
  - `go test ./...`

Observable proof for S02 is not “Argo is Synced” yet; that belongs to S03. S02 is done when release-rendered desired state and Argo handoff metadata encode one explicit contract: required identity labels remain on workload/pod-template/Application surfaces, `otel.devflow.io/*` annotations remain supplementary on the Argo/Tekton side, and drift-prone annotations like `kubectl.kubernetes.io/restartedAt` are no longer emitted into the wrong desired-state surfaces by default.

## Constraints

- `buildReleaseWorkloadResource` is shared across rolling `Deployment` and future `Rollout` rendering, so any contract helper must remain rollout-kind agnostic to support R041 later.
- Runtime-side consumers already require `devflow.io/release-id`, `devflow.application/id`, and `devflow.environment/id`; any “cleanup” that weakens or renames those labels will break runtime correlation.
- The repo already contains a narrow `ignoreDifferences` rule for restartedAt. Per D013/R047, S02 should not broaden ignore rules as the primary fix; it should reduce drift-prone desired-state metadata emission first.

## Common Pitfalls

- **Changing runtime-service instead of the renderer** — `internal/runtime/service/service.go` owns a live restart signal, but S02’s contract problem is primarily that release rendering copies annotations too broadly. Fix the producer seam first.
- **Treating trace/span as workload identity** — the runtime observer code does not consume `otel.devflow.io/*`; any new tests/docs should reinforce that missing trace/span is an observability gap, not a correlation failure.
- **Hard-coding Deployment-only assumptions in tests/helpers** — `buildReleaseWorkloadResource` also emits Argo `Rollout` objects for canary/blueGreen; keep contract assertions about metadata surfaces generic across workload kinds.

## Open Risks

- S01 proved that restartedAt is the known drift candidate, but not whether other workload snapshot annotations are also unsafe on desired-state surfaces. The implementation should likely use an explicit allowlist/denylist policy rather than a one-off restartedAt special case hidden in ad hoc logic.
- `deriveReleaseRolloutContext` still falls back to persisted workload environment when the environment label is absent. That fallback is tolerable today, but if S02 changes docs/tests carelessly it could obscure the stronger intended contract that labels remain primary.
